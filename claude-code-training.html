Claude Code で成果物を作る

コンサル・新規事業担当者向け研修資料。
Claude Code を「安全に始め、成果物を作り、品質を仕組みで固定する」までを一気通貫で学びます。

AI活用研修 Claude Code 成果物づくり 品質の仕組み化

00 ／ GOAL

研修のゴール

要点 本研修を終えると、Claude Code を「安全に始め、成果物を作り、品質を仕組みで固定する」一連の流れを、自分の業務で回せるようになります。

到達目標

  • Claude Code で何が作れるか（ツール／自動化／データ処理／複数ファイル編集）を説明できる
  • Desktop（基本）で安全に始め、適切に指示を出せる
  • データ処理・複数ファイル作業を任せて成果物にできる
  • ツール／プロトタイプ／簡単なアプリを作れる
  • CLAUDE.md でルールを固定し、Skills で手順を型化して、成果物の質と再現性を上げられる
  • Subagents で作業を分担・並列化し、大きめの成果物づくりを効率化できる

SECTION 01

Claude Code を知る・始める

AIエージェントとは何かを理解し、何が作れるかを地図として押さえる。作業用フォルダと安全な指示の型を整え、安心して任せられる状態を作る。

1.1 「AIエージェント」とは — 相談役から相棒へ

要点 これまでの Chat は聞けば答える「相談役」。エージェントはゴールを伝えると、段取り・実行・仕上げまで自分で進める「相棒」です。

依頼例：「明日の企画書、構成案と裏付け調査をお願い」と頼んだとき——

相談役（これまでの Chat）

きれいな構成案を返して終わり。
「完璧な構成案です。あとはご自身で調査して、資料に仕上げてください」

アイデアはくれるが、手を動かすのは結局こちら。返ってくるのは「下書きのタネ」。

相棒（エージェント）

調べて、書いて、資料まで仕上げる。
やることリスト → 調べる → 本文を書く → 資料に仕上げる

こちらは出てきたものを確認するだけ。返ってくるのは「ほぼ仕上がった成果物」。

1

段取りを考える

ゴールから「何をすべきか」を自分で計画する

2

自律的に進める

複数のステップを続けて実行する

3

道具を使って完結

検索・ファイル操作などを組み合わせて仕上げる

人間の役割エージェントの役割
ゴールを決める／成果物を確認し、採用・修正・やり直しを最終判断する段取り・道具の操作・仕上げまでの「間の作業」を進める

1.2 Claude Code とは — 成果物作成の3つのレベル

要点 Claude Code は、ゴールを伝えるとファイルを直接読み書きして作業を進める環境。コードを書く必要はなく、日本語で依頼するだけでよい。
レベル環境できること
簡易Artifact診断ツール、画面モック、シミュレーター — その場の試作。認識合わせ・たたき台に
中級Cowork手元のファイル群を使った成果物 — レポート、集計表。ローカルフォルダでのファイル作業
高度Claude Codeデータ処理、複数画面、保存・再利用できるツール — より大きく・繰り返し使える成果物

Artifact / Cowork が入口、Claude Code がもう一歩先。

1.3 Claude Code で作れるもの

要点 共通するのは「保存できる・繰り返し使える・チームで共有できる」。その場限りだった作業を、何度でも使える仕組みに変えられる。

CSV / Excel 分析ツール

大量データの集計・グラフ化・レポート生成を自動化

簡易ダッシュボード

複数データソースを統合した KPI 表示画面

複数ファイルの整理

散在するファイルを読み取り、分類・統合・レポート化

プロトタイプの本格化

Artifact の試作品を保存・複数画面対応に発展

社内向けミニツール

見積計算、申請フォーム、チェックリスト

定型レポート生成

毎月の報告書をテンプレートとデータから自動生成

「作る」だけでなく「調べる・考える」にも使える — 複数エージェントの手分けでリサーチ・企画にも広がる（Section 04）。

1.4 Chat・Cowork・Claude Code の使い分け

要点 やりとりの単位で選ぶ — 1回性のやりとりは Chat、手元のファイル群は Cowork、プロジェクトフォルダ単位の横断作業は Claude Code。
手段向いている場面
Chatファイルを貼って直してもらう。都度貼り直し・受け取って配置する一回性のやりとり
Cowork手元のファイル群（Word・Excel・PDF・画像）を読ませて整理・要約・成果物化する
Claude Codeプロジェクトフォルダ単位で、複数ファイルを横断した分析・ツール構築・自動化を行う

1.5 どこで動かすか — Desktop / IDE / CLI

要点 最初は Desktop から始めると迷わない。CLI や IDE は、並列作業や自動化を求めるようになってから検討すれば十分。
環境特徴
Desktop（推奨）まず試す／ファイル中心で使う。軽快で初心者向け。Cowork との切り替えもスムーズ
IDE（VS Code / Cursor / JetBrains 拡張）エディタ画面の中で作業が完結。成果物・変更箇所（差分）を見ながら進めたい人向け
CLI（ターミナル）複数の Claude Code を同時起動して並行で進められる。自動化・繰り返し実行が得意

1.6 始める前の準備と最初の一歩

要点 まず作業用フォルダを切り、元データの直接編集を避ける。最初の指示は作業ではなく「まず中身を見てもらう」1文から始めると安全。
1

アプリを起動

Claude デスクトップアプリを開く

2

Claude Code を開く

メニューから選択（Cowork と同じ画面まわり）

3

作業フォルダを開く

元データのコピーを入れた作業用フォルダを指定

4

最初の指示を試す

いきなり作業を頼まず、状況把握から

🤖 最初の1回はこう打つ

このフォルダに何のファイルがあるか、一覧と内容の概要を教えて。まだ何も変更しないで。

1.7 最初に必ず出る「許可しますか？」の答え方

要点 確認ダイアログは暴走を防ぐ安全装置。止まったと勘違いせず、落ち着いて答えればよい。迷ったら「1回だけ許可」が安全。
選択肢意味・使いどころ
1回だけ許可この1回だけ実行を認める。次の作業ではまた確認が出る。中身をよく見てから進めたいときに使う
常に許可同じフォルダ内の同種の操作（読み込みなど）は次回から確認なし。安全だと納得できた操作だけに使う

「常に許可」した操作はその作業フォルダ内では次から省かれ、だんだんスムーズになる。作業フォルダの外を触ろうとしたときほど、中身を確かめてから答える。

1.8 安全な指示の出し方 — 5つの原則

指示が曖昧だと意図しない変更が起きます。次の5点を最初の指示に含めます。

  1. 目的と成果物を最初に伝える — 「何のために」「最終的に何を出すか」を言語化する
  2. 変更対象を明確にする — 「○○ファイルの△△を修正して」。「全体を良くして」は避ける
  3. 禁止事項を明示する — 「○○は変更しないで」「既存のデータは消さないで」を先に伝える
  4. 完了条件を決めておく — 「これが満たされたら完了」。レビュー基準にもなる
  5. 小さな単位で進める — 「まず○○を作って → 確認 → 次に△△を追加」と段階的に

⚠️ 最終責任は人間

Claude Code は「手を動かすアシスタント」であり「責任者」ではありません。生成物の最終責任は自分。数値の正確性と、既存部分が壊れていないかを重点チェックします。

SECTION 02

成果物を作る — データ処理とツール

Claude Code が特に得意な「データ処理・複数ファイルの横断作業」から始め、Artifact の延長で保存・再利用できるツールへ発展させる。

2.1 データ処理・複数ファイルを任せる

要点 Claude Code が「集める・整える・まとめる」（下ごしらえ）を担い、自分は「分析・判断」（価値を出す仕事）に集中する。

アンケート・調査データのクロス集計

設問・セグメント別に集計し、自由回答はカテゴリ分類して比較表に

インタビュー逐語録の整理

複数の逐語録から論点・発言を抽出して一覧に

競合IR・財務データの横断比較

複数社の開示情報を統合し、比較表を自動生成

定型調査レポートの生成

テンプレートとデータから定例レポートのドラフトを生成

2.2 作る流れ — 4ステップ

1

目的と成果物を1行で

「月次売上CSVを統合して拠点別の集計表（Excel）を作る」

2

対象範囲を限定

「対象は◯◯フォルダのCSVだけ。元ファイルは変更せず新ファイルに出力して」

3

計画を出させてから実装

「まず実装せず、読み込むファイルと集計方針を説明して」

4

出力を動作確認

数値が元データと合っているか、抜け漏れがないかを自分で確認

2.3 活用例 — アンケート・調査データを集計する

1

データを作業フォルダに

元ファイルのコピーを入れる。直接編集させないための準備

2

統合・集計を依頼

「統合して設問・セグメント別にクロス集計、自由回答は分類して比較表に」

3

新ファイルとして保存

「集計表を新しいファイルとして保存して」。成果物は別ファイルに

4

照合して報告書へ

数値・金額・固有名詞は元データと必ず照合

⚠️ データの扱い

元データは作業コピーで扱い、出力は必ず人が確認する。特に数値・金額・固有名詞は元データと照合してから使う。顧客データ・アンケート結果・機密資料は特に慎重に。

2.4 ツール・プロトタイプ — Artifact との違い

要点 Artifact（その場かぎりの試作）を、保存できて・複数画面があって・繰り返し使えるツールに発展させる。認識合わせが速くなり、案件をまたいで使い回せる。

Artifact（第1回）

その場で動く試作品。1画面・データ保存なし。認識合わせ・たたき台に最適。

Claude Code

ファイルとして保存・再利用できる。複数画面・データの読み書きに対応。社内ミニツールとして継続利用できる。

2.5 作れるツールの例 — コンサル・新規事業向き

セグメンテーション診断ツール

回答すると顧客セグメントや適合度スコアとアドバイスが出る

市場規模・価格シミュレーター

TAM/SAM/SOM を算出。価格弾力性シミュレーションにも

競合比較ダッシュボード

複数社の価格・機能・シェアをグラフで一覧表示

ポジショニングマップ生成ツール

2軸を入力すると競合・自社の位置づけを可視化

NPS・認知度トラッカー

定点調査の結果を時系列で入力し、推移をグラフ化

競合・市場情報の検索ツール

手元の調査資料一覧をキーワードで絞り込む

2.6 ツールの作り方 — 4ステップ

1

目的と使う人を伝える

「営業が提案時に使う、簡単な市場規模算出ツール」

2

たたき台を生成

まず動く最小版を作らせ、すぐ操作して確認

3

操作して修正を繰り返す

「項目を増やして」「結果をグラフに」と段階的に育てる

4

保存・共有

ブラウザで開くだけで使える形にして共有

⚠️ 試作品であることを明示

作るのは「試作品・社内ツール」であり本番システムではありません。多人数利用や個人情報・機密データを扱う仕組みは別途設計が必要。クライアントに見せる際は「試作品です」と明記する。

SECTION 03

質を固定する道具 — CLAUDE.md・Skills・MCP

成果物を繰り返し作るようになると、毎回品質がブレない仕組みが欲しくなる。ルールの固定・手順の型化・データの接続で、質と再現性を固定する。

3.1 3つの道具の全体像

要点 常に守るルールの上で、型化した手順と道具を使い、足りないデータを取り寄せる。3つが揃うと依頼文は短くなり、毎回同じ品質が返ってくる。
道具役割発動たとえ
CLAUDE.md常に守るルール（文体・体裁・禁止事項）毎回自動で読み込まれる店の決まり — 開店中ずっと守る約束事
Skillsレシピ＋道具箱（議事録の型・週報づくり）呼ばれたときに動くレシピ本と調理道具 — 料理に応じて取り出す
MCP材料の取り寄せ（Notion・Slack など社内サービス接続）必要なときに接続材料の買い出し — 足りない食材を取り寄せる
式で言うと ルール（常時） × 手順（型） × データ（接続） ＝ 依頼文は短く、毎回同じ品質の成果物。

3.2 CLAUDE.md — 「毎回説明し直していること」を書いておく場所

要点 CLAUDE.md は Claude Code が自動で読み込むルールファイル。会話のたびに同じ注意を繰り返さなくても、品質を一定に保てる。

書くべきこと

プロジェクトの概要、ファイル構成、守るルール、禁止事項、出力形式のルール、レビュー基準

書かなくてよいこと

一般的な知識、一時的な作業指示（それはチャットで伝える）

迷ったら「次の会話でも説明し直すか？」— し直すことなら書く。ルールは後から自分で確認できるくらい具体的に（「結論から書く」ではなく「冒頭1段落に結論・根拠・アクションの3点を入れる」）。曖昧な表現は Claude が独自解釈し、毎回ブレる原因になる。

3.3 案件用 CLAUDE.md の例 — B社 中期計画支援

箇条書きで書くだけでよく、特別な書き方は要りません。

  • 概要：B社（食品メーカー）の中期経営計画策定支援。成果物は経営会議向け資料
  • フォルダの使い方：01_受領資料／は読むだけ（変更しない）、02_作業中／にドラフト、03_納品／は確定版のみ
  • 守るルール：です・ます調、結論から書く。社名は「B社」と表記
  • 禁止事項：01_受領資料／の中のファイルは変更しない
  • 出力形式：報告資料は1スライド1メッセージ

CLAUDE.md はチームの「品質基準書」— 共有すれば全員が同じルール・同じ前提で Claude Code を使え、成果物の品質が揃う。

3.4 CLAUDE.md の置き場所 — 自分用と案件用の2段

自分用（グローバル）案件用（プロジェクト）
場所PC の設定フォルダ（.claude）に1つ作業フォルダとして開くフォルダの直下
適用自分が関わるすべての作業その案件だけに適用
例結論から書く／です・ます調 ＝ 自分の流儀クライアントは B社／成果物の体裁／レビュー観点
特長/memory で開ける（場所は覚えなくてよい）チーム共有でき、全員が同じ前提で動ける

両方とも効く（重ねて読み込まれる）。内容がぶつかったときは、より具体的な案件用が優先。

⚠️ 作業フォルダはローカルに

作業フォルダは必ず自分の PC 上（ローカル）に作る — Google ドライブ・BOX などのクラウド共有には直接つながない。クラウド上のファイルは、いったんローカルの作業用フォルダにコピーして使う。

3.5 どう作る？ — /init・/memory・自動メモリ

要点 チャット入力欄に打つだけの「スラッシュコマンド」で、たたき台生成から確認・編集まで完結する。コマンドを使わず「CLAUDE.md にまとめて」でもよい。
コマンドできること
/init案件フォルダを開いた状態で打つと、中身から CLAUDE.md を自動生成。既存があれば上書きせず改善点を提案
/memory読み込まれている CLAUDE.md（自分用／案件用）を確認・追記。自動メモリの中身もここで確認・編集
自動メモリClaude が自分でメモを取る。修正パターン・好み・作業ログを次のセッションに引き継ぐ。「これを覚えておいて」で保存される

あなたが書くルール（CLAUDE.md）＋ Claude が自ら書くメモ（自動メモリ）。反映されるのは「新しい会話」から — 作ったら・変えたら、新しい会話で始める。

3.6 応用 — ルールファイルは役割別に小さく分ける

要点 CLAUDE.md は「インデックス」、各 .md は「個別の章」。1ファイルに全部書くと、どのルールを優先するか判断しづらくなる。
ファイル役割
DESIGN.md見た目のトンマナ、配色、体裁。非デザイナーでも一定品質を保てる
CONTENT.md文体・用語・構成パターン・「書かないこと」のルール
REVIEW.mdレビュー観点と合格基準。誰がレビューしても同じ目線でチェックできる
PROGRESS.md経過・決定事項・残タスク。「作業開始時に PROGRESS.md も読んで」で会話をまたいで引き継げる

CLAUDE.md からは「詳しくは○○.md を参照」と参照する。

3.7 Skills — よく使う手順を型にする

要点 手順・ルール・出力形式を型として保存し、呼び出すだけで同じ品質の成果物を作る。AI の柔軟さと決まった処理の正確さを両立できる。

例：Skill「競合ウォッチ週報」の中身 — 4点セット

要素中身
指示書（中心）「競合の動きを整理 → 自社への示唆 → 次アクション」の手順と、いつ使うか
テンプレート・素材週報のひな型（見出し・表の体裁・トンマナ）
決まった処理社名・製品名の表記ゆれを正式名称に一括統一
参照資料自社の競合定義・用語集（必要なときだけ読む補足）

Skill 化の3条件 — ①繰り返し発生する ②手順が明確 ③品質基準がある。3つが揃う作業が Skill 向き。

3.8 Skills の育て方と共有

要点 最初から完成形を目指さない。まず指示文だけ、あとから道具を足す。プログラムを書く必要はなく、束ねる作業も Claude に頼めばよい。
1

手順を文章で書く

うまくいった依頼文を書き起こす。「この手順を Skill にして」で下書きしてくれる

2

道具を足す

テンプレート・決まった処理・参照資料を後付けで束ねる

3

使って直す

発動するか・品質・手間の3点を見ながら「自分仕様」に育てる

呼び出しは名指しが確実 — 「競合ウォッチ週報の Skill で今週分を作って」。Skill の実体はファイル一式で、そのまま配布でき、属人化しがちな「うまいやり方」がチームの標準になる。

実例 800社スキル集 consulting-toolkit-800（調査提案書・デスクリサーチ・インタビュー設計・議事録・報告書骨子・スライド構成）。マーケットプレイス「eight-hundred-inc/consulting-toolkit-800」から導入。

📦 e-Grid Consulting Toolkit（社内配布）

イーグリッド独自のスキル集（e-Grid風スライド生成・調査提案書・議事録・デスクリサーチ 等）は Google Drive の共有フォルダから配布しています。導入手順は 導入マニュアル（Mac / Windows） を参照してください。

3.9 MCP / Connectors — 必要なデータを接続する

要点 成果物の質は「渡す情報の質」で決まる。Notion・Slack などの社内情報を接続すれば、自社の文脈を踏まえた成果物が一度の依頼で作れる。
  • 仕組みはシンプル — claude.ai 設定の「コネクタ」＝ MCP。「Claude と外部サービスをつなぐ口」と理解すれば十分
  • つなぎ方 — デスクトップアプリの設定（コネクタ）からサービスを追加し、案内に沿ってログイン・許可。/mcp で接続一覧を確認
  • 例 — 社内の Notion を接続すれば「先週の定例の議事メモを踏まえて論点を整理して」がコピペなしで通る
  • PC 上のフォルダなら接続不要 — 作業フォルダに置けばそのまま読める

⚠️ 接続の原則

①必要な情報だけ渡す（ノイズは品質を下げる）②適切な粒度で渡す ③権限・機密に注意（アクセス権のある情報に限定し、機密・権限外は不用意につながない）。

SECTION 04

使いこなす — Subagents・実践TIPS

大きめ・複雑な成果物を効率よく作るための使いこなし。Subagents で作業を分担・並列化し、スラッシュコマンドと立て直しの型で日々の作業を安定させる。

4.1 Subagents — 作業を分担・並列化する

要点 1つの大きなタスクを「調べる人・作る人・チェックする人」に分ける。ゴールを渡せば、手分け〜統合の段取りはメインエージェントが組む。
役割担当すること
あなた（人間）ゴールを渡す。最後に成果を確認し、採用・修正・やり直しを判断する
メインエージェント（親）あなたと話す AI 本体。自分でサブに手分けし、戻ってきた要約を統合する
サブ1：調査担当必要な情報・ファイルの収集と整理を専門に担当
サブ2：実装担当実際のファイル作成・修正・成果物づくりを担当
サブ3：レビュー担当成果物の品質チェック・抜け漏れ確認を担当

サブエージェント（子）は並列で作業し、要約だけをメインに返す。調査は並列、レビューは成果物が揃ってから — この段取りも親が組む。確実に使いたいときは「サブエージェントで手分けして」と一言入れる。

4.2 なぜ強いのか — 「机のたとえ」と「独立した目」

要点 手分けして要約だけを返せば親の机（一度に扱える情報量）が空いたままになり、役割を分ければ批判が甘くならない。

使う

情報量が多く1つの会話では精度が落ちる／作業を並列に分けられる／違う視点が欲しい

使わない

簡単・短い・手順が一直線の作業（過剰になるので単体の Claude Code で OK）

  • 1体の AI は「作業机」に限りがある — 書類（情報）で埋まると判断が鈍る。手分け＋要約返却で机を空ける
  • 同じ AI に「作って」と「批判して」を同時に頼むと立場が混ざる — 役割を分けると各自が本気で役目を果たす

⚠️ 注意

背景（目的・前提・判断基準）を渡さないと、たくさん動く分だけ的外れになりやすい。最初は1つの Claude Code で十分。「分担した方が速い」と感じたら取り入れる。

4.3 リサーチの型・アイデアの型 — そのまま使える例文

要点 カギは「独立した目」と「広さ」。従来は複数の AI に投げてコピペ統合していた工程が、一度の依頼で通せる。
1

観点別に並列調査

複数の担当が同時に異なる観点を調べる

2

親が統合

要約だけを受け取り全体をまとめる

3

別担当が検証

抜けと根拠の弱い点を独立チェック

4

1枚にまとめる

広く深く、抜けの少ない成果物に

🤖 リサーチ例文

競合3社を「価格・提供価値・顧客層」の3観点でサブエージェントに手分けして並列で調べて。統合したら、別の担当に抜けと根拠の弱い点をチェックさせ、最後に1枚の比較表にまとめて。

🤖 アイデア例文

新サービスの名称を考えたい。まず命名の成功パターンを調べ、次に案を20個発散し、別の評価役に「覚えやすさ・独自性・既存名との重複」で採点させて上位5案に絞って。

4.4 コラム — 思考フレームワークを Subagents に載せる

シックスハット（6つの帽子）の「1つの視点＝1人の担当」に分ければ、テーマを抜けなく検証できます。企画の評価・提案の事前レビュー・打ち手の比較に。

視点（帽子）担当すること
事実（白）データ・客観情報だけを集め、「分かっていること／いないこと」を仕分ける
感情（赤）使う人・受け手がどう感じるか。好き嫌い・期待・不安を言語化
リスク（黒）弱点・懸念・失敗しうる点を厳しく指摘。批判専門なので遠慮なく
メリット（黄）価値・うまくいく理由・得られる効果を前向きに洗い出す
新発想（緑）代替案・別の切り口・改善アイデアを自由に発想
統括（青）他の5人の結果を整理して結論にまとめる（あなたの統合役）
Skills と Subagents Skills は「どうやるか」（手順の型）、Subagents は「誰が（何人で）やるか」（分担）。役割が違うので組み合わせて使える。

4.5 実践 TIPS — スラッシュコマンドと小ワザ

すべて覚える必要はありません。使えそうなものから取り入れる。コマンドの最新一覧は /help で確認できます。

コマンド／小ワザ効果
/context机の埋まり具合を見る（会話履歴の使用量確認）
/compact要点だけ残して机を片付ける（同じ作業を続けるとき）
/clear全部下げてまっさらにする（別の作業に移るとき）
パスのコピーWin：右クリック「パスのコピー」／Mac：Opt+⌘+C。フォルダ外のファイルも渡せる
/effort思考の深さを調整。複雑な作業は深く、軽い作業はデフォルトで十分
ESC 2回・↑キー（CLI / IDE）直前指示への巻き戻し／過去指示の再利用

並行作業 — 「案件＝フォルダ＝会話」を1対1に。同じフォルダを複数会話で同時変更しない。

4.6 うまく動かない時の立て直し方

要点 「もっと強い指示を出す」より「準備に戻る」のが効く。打ち手は順番ではなく、状況に応じて選ぶ。
  • まず、止めてよい — 停止ボタン（または ESC）でいつでも止める。「今どこまで進んだ？」と確認してから打ち手を選ぶ
  • 新しい会話で仕切り直す — 冒頭に「目的／いまの状況／残っている課題」を1段落で書いてから依頼し直す
  • 作業を1ステップに切る — 「まず◯◯だけ直して。終わったら報告して、次の指示を待って」
  • 対象ファイル・範囲を限定する — 「対象は◯◯フォルダの△△だけ。ほかは読まず・変更しないで」
  • 現状を棚卸しさせる — 「変更する前に、今このファイルがどうなっていて、何が問題か説明して」

それでも長引くときは、2.2 の基本（作業フォルダ／目的と成果物／変更対象／禁止事項／完了条件）を整え直すのが近道。指示を強くするより前提を整え直す。
