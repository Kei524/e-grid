研修のゴール

本研修を終えると、Claude Code を「安全に始め、成果物を作り、品質を仕組みで固定する」一連の流れを自分の業務で回せるようになる。

  • Claude Code で何が作れるか（ツール／自動化／データ処理／複数ファイル編集）を説明できる
  • Desktop（基本）で安全に始め、適切に指示を出せる
  • データ処理・複数ファイル作業を任せて成果物にできる
  • ツール／プロトタイプ／簡単なアプリを作れる
  • CLAUDE.md でルールを固定し、Skills で手順を型化して、成果物の質と再現性を上げられる
  • Subagents で作業を分担・並列化し、大きめの成果物づくりを効率化できる

1.2

Claude Code とは — 成果物作成の3つのレベル

Claude Code は、ゴールを伝えるとファイルを直接読み書きして作業を進める環境。コードを書く必要はなく、日本語で依頼するだけでよい。

TRN-2026-CC026 / 38
1.3

Claude Code で作れるもの

共通するのは「保存できる・繰り返し使える・チームで共有できる」。その場限りだった作業を、何度でも使える仕組みに変えられる。

代表的な成果物
  • CSV / Excel 分析ツール — 大量データの集計・グラフ化・レポート生成を自動化
  • 簡易ダッシュボード — 複数データソースを統合した KPI 表示画面
  • 複数ファイルの整理 — 散在するファイルを読み取り、分類・統合・レポート化
  • プロトタイプの本格化 — Artifact の試作品を保存・複数画面対応に発展
  • 社内向けミニツール — 見積計算、申請フォーム、チェックリスト
  • 定型レポート生成 — 毎月の報告書をテンプレートとデータから自動生成
「作る」だけでなく「調べる・考える」にも使える — 複数エージェントの手分けでリサーチ・企画にも広がる（Section 04）。

どこで動かすか — Desktop / IDE / CLI

最初は Desktop から始めると迷わない。CLI や IDE は、並列作業や自動化を求めるようになってから検討すれば十分。

1.6

始める前の準備と最初の一歩

まず作業用フォルダを切り、元データの直接編集を避ける。最初の指示は作業ではなく「まず中身を見てもらう」1文から始めると安全。

最初の1回はこう打つ — 「このフォルダに何のファイルがあるか、一覧と内容の概要を教えて。まだ何も変更しないで。」
TRN-2026-CC0210 / 38
1.7

最初に必ず出る「許可しますか？」の答え方

確認ダイアログは暴走を防ぐ安全装置。止まったと勘違いせず、落ち着いて答えればよい。迷ったら「1回だけ許可」が安全。

  • 「常に許可」した操作はその作業フォルダ内では次から省かれ、だんだんスムーズになる
  • 作業フォルダの外を触ろうとしたときほど、中身を確かめてから答える
TRN-2026-CC0211 / 38
1.8

安全な指示の出し方 — 5つの原則

指示が曖昧だと意図しない変更が起きる。次の5点を最初の指示に含める。

  • 1. 目的と成果物を最初に伝える — 「何のために」「最終的に何を出すか」を言語化する
  • 2. 変更対象を明確にする — 「○○ファイルの△△を修正して」。「全体を良くして」は避ける
  • 3. 禁止事項を明示する — 「○○は変更しないで」「既存のデータは消さないで」を先に伝える
  • 4. 完了条件を決めておく — 「これが満たされたら完了」。レビュー基準にもなる
  • 5. 小さな単位で進める — 「まず○○を作って → 確認 → 次に△△を追加」と段階的に
Claude Code は「手を動かすアシスタント」であり「責任者」ではない — 生成物の最終責任は自分。数値の正確性と既存部分が壊れていないかを重点チェックする。

Section 02

成果物を作る — データ処理とツール

Claude Code が特に得意な「データ処理・複数ファイルの横断作業」から始め、Artifact の延長で保存・再利用できるツールへ発展させる（2-3 / 2-4）。

TRN-2026-CC0213 / 38
2.1

データ処理・複数ファイルを任せる

Claude Code が「集める・整える・まとめる」（下ごしらえ）を担い、自分は「分析・判断」（価値を出す仕事）に集中する。

コンサル・新規事業で作れる成果物
  • アンケート・調査データのクロス集計 — 設問・セグメント別に集計し、自由回答はカテゴリ分類して比較表に
  • インタビュー逐語録の整理 — 複数の逐語録から論点・発言を抽出して一覧に
  • 競合IR・財務データの横断比較 — 複数社の開示情報を統合し、比較表を自動生成
  • 定型調査レポートの生成 — テンプレートとデータから定例レポートのドラフトを生成
手作業で時間がかかる「集める・整える・まとめる」を委任し、人は分析・判断に時間を使う。

作れるツールの例 — コンサル・新規事業向き

提案・調査・企画の現場でそのまま使える小さなツールが、日本語の依頼だけで作れる。

ツール例

  • 競合・市場情報の検索ツール — 手元の調査資料一覧をキーワードで絞り込む

2.6

ツールの作り方 — 4ステップ

まず動く最小版を作らせ、操作しながら段階的に育てる。一気に作り込ませないのがコツ。

作るのは「試作品・社内ツール」であり本番システムではない — 多人数利用や個人情報・機密データを扱う仕組みは別途設計が必要。クライアントに見せる際は「試作品です」と明記する。

Section 03

3.2

CLAUDE.md — 「毎回説明し直していること」を書いておく場所

CLAUDE.md は Claude Code が自動で読み込むルールファイル。会話のたびに同じ注意を繰り返さなくても、品質を一定に保てる。

  • ルールは後から自分で確認できるくらい具体的に — 「結論から書く」ではなく「冒頭1段落に結論・根拠・アクションの3点を入れる」
  • 曖昧な表現は Claude が独自解釈し、毎回ブレる原因になる
TRN-2026-CC0222 / 38
3.3

案件用 CLAUDE.md の例 — B社 中期計画支援

箇条書きで書くだけでよく、特別な書き方は要らない。準備・指示の基本がファイルに固定され、毎回口頭で伝えずに済む。

  • 概要：B社（食品メーカー）の中期経営計画策定支援。成果物は経営会議向け資料
  • フォルダの使い方：01_受領資料／は読むだけ（変更しない）、02_作業中／にドラフト、03_納品／は確定版のみ
  • 守るルール：です・ます調、結論から書く。社名は「B社」と表記
  • 禁止事項：01_受領資料／の中のファイルは変更しない
  • 出力形式：報告資料は1スライド1メッセージ
CLAUDE.md はチームの「品質基準書」— 共有すれば全員が同じルール・同じ前提で Claude Code を使え、成果物の品質が揃う。

  • 実例：800社スキル集 consulting-toolkit-800（調査提案書・デスクリサーチ・インタビュー設計・議事録・報告書骨子・スライド構成）。マーケットプレイス「eight-hundred-inc/consulting-toolkit-800」から導入

3.9

MCP / Connectors — 必要なデータを接続する

成果物の質は「渡す情報の質」で決まる。Notion・Slack などの社内情報を接続すれば、自社の文脈を踏まえた成果物が一度の依頼で作れる。

  • 仕組みはシンプル — claude.ai 設定の「コネクタ」＝ MCP。「Claude と外部サービスをつなぐ口」と理解すれば十分
  • つなぎ方 — デスクトップアプリの設定（コネクタ）からサービスを追加し、案内に沿ってログイン・許可。/mcp で接続一覧を確認
  • 例 — 社内の Notion を接続すれば「先週の定例の議事メモを踏まえて論点を整理して」がコピペなしで通る
  • PC 上のフォルダなら接続不要 — 作業フォルダに置けばそのまま読める
接続の原則 — ①必要な情報だけ渡す（ノイズは品質を下げる）②適切な粒度で渡す ③権限・機密に注意（アクセス権のある情報に限定し、機密・権限外は不用意につながない）。

Section 04

使いこなす — Subagents・実践TIPS

大きめ・複雑な成果物を効率よく作るための使いこなし。Subagents で作業を分担・並列化し、スラッシュコマンドと立て直しの型で日々の作業を安定させる（2-6 / 2-7）。

4.2

なぜ強いのか — 「机のたとえ」と「独立した目」

手分けして要約だけを返せば親の机（一度に扱える情報量）が空いたままになり、役割を分ければ批判が甘くならない。

  • 1体の AI は「作業机」に限りがある — 書類（情報）で埋まると判断が鈍る。手分け＋要約返却で机を空ける
  • 同じ AI に「作って」と「批判して」を同時に頼むと立場が混ざる — 役割を分けると各自が本気で役目を果たす
  • 注意：背景（目的・前提・判断基準）を渡さないと、たくさん動く分だけ的外れになりやすい
TRN-2026-CC0232 / 38
4.3

リサーチの型・アイデアの型 — そのまま使える例文

カギは「独立した目」と「広さ」。従来は複数の AI に投げてコピペ統合していた工程が、一度の依頼で通せる。

コラム — 思考フレームワークを Subagents に載せる

シックスハット（6つの帽子）の「1つの視点＝1人の担当」に分ければ、テーマを抜けなく検証できる。企画の評価・提案の事前レビュー・打ち手の比較に。

6つの視点 ＝ 6人の担当
  • 事実（白） — データ・客観情報だけを集め、「分かっていること／いないこと」を仕分ける
  • 感情（赤） — 使う人・受け手がどう感じるか。好き嫌い・期待・不安を言語化
  • リスク（黒） — 弱点・懸念・失敗しうる点を厳しく指摘。批判専門なので遠慮なく
  • メリット（黄） — 価値・うまくいく理由・得られる効果を前向きに洗い出す
  • 新発想（緑） — 代替案・別の切り口・改善アイデアを自由に発想
  • 統括（青） — 他の5人の結果を整理して結論にまとめる（あなたの統合役）
Skills は「どうやるか」（手順の型）、Subagents は「誰が（何人で）やるか」（分担）。役割が違うので組み合わせて使える。

うまく動かない時の立て直し方

「もっと強い指示を出す」より「準備に戻る」のが効く。打ち手は順番ではなく、状況に応じて選ぶ。

  • まず、止めてよい — 停止ボタン（または ESC）でいつでも止める。「今どこまで進んだ？」と確認してから打ち手を選ぶ
  • 新しい会話で仕切り直す — 冒頭に「目的／いまの状況／残っている課題」を1段落で書いてから依頼し直す
  • 作業を1ステップに切る — 「まず◯◯だけ直して。終わったら報告して、次の指示を待って」
  • 対象ファイル・範囲を限定する — 「対象は◯◯フォルダの△△だけ。ほかは読まず・変更しないで」
  • 現状を棚卸しさせる — 「変更する前に、今このファイルがどうなっていて、何が問題か説明して」
それでも長引くときは、2-2 の基本（作業フォルダ／目的と成果物／変更対象／禁止事項／完了条件）を整え直すのが近道。指示を強くするより前提を整え直す。

まとめ — Claude Code で成果物を作る

  • 知る・始める — 何が作れるかを地図として押さえ、Desktop＋作業用フォルダ＋安全な指示の型（目的／変更対象／禁止事項／完了条件）で始める
  • 作る — ①データ処理・複数ファイル（集める・整える・まとめるを任せる）②ツール・プロトタイプ（保存・再利用できる形に育てる）
  • 質を固定する — CLAUDE.md でルールを固定し、Skills で手順を型化し、MCP で必要なデータを接続する
  • 使いこなす — Subagents で調査・実装・レビューを分担／並列化。困ったら「強い指示」より「準備に戻る」
  • 出力は常に「初稿」 — 最終的な確認と承認は人間が行い、責任を持つ
